# HumanThread Web 工作台页面骨架

> 日期：2026-05-19
> 状态：Web 工作台界面基线
> 方向：Teambition 式协作工作台，GitHub 式线条、按钮、留白和信息密度

## 1. 已锁定决策

- Web 端默认首页是 `我的工作台`。
- 产品形态偏协作工作台，不做后台管理系统。
- GitHub 只作为视觉语言参考，不照搬 GitHub 的信息结构。
- 页面骨架采用 `轻侧栏 + 内容区`。
- 首页采用 `当前任务优先 + 双栏工作台`。
- 首页右侧第一块展示 `工作流时间线`。
- 首页当前任务主区采用 `控制台风格`，强调立即推进。
- `Windows / Linux` 客户端属于横向补齐，不阻塞 Web 工作台纵向完善。

## 2. 全局壳层

### 2.0 路由切换反馈

- 不注册路由级 `loading.tsx` 暂缓页面，不使用固定骨架替换用户当前页面。
- 页面切换期间保留当前页面内容，由全局顶部细进度条提供即时、非阻塞的导航反馈。
- 组件内部的数据请求、表单提交和命令执行继续使用各自真实的 loading/pending 状态。

### 2.1 路由

| 页面 | 路由 | 作用 |
| --- | --- | --- |
| 我的工作台 | `/` 或 `/workbench` | 默认首页，聚焦当前人类线程 |
| 团队协作 | `/team` | 查看团队成员当前占用、队列和阻塞 |
| 项目空间 | `/projects` | 以项目为上下文发起事项和查看项目工作流 |
| 工作流详情 | `/workflows/[workflowId]` | 查看单个工作流的任务链、时间线和上下文 |

### 2.2 布局

- 左侧轻侧栏宽度约 `220px`。
- 内容区使用 GitHub 风格的窄边框容器和分区。
- 页面主容器最大宽度控制在 `1280px` 左右。
- 面板圆角控制在 `6-8px`。
- 边框优先使用 `#d0d7de`，背景优先使用 `#f6f8fa` 和 `#ffffff`。
- 主操作按钮使用接近 GitHub 的绿色，次操作使用白底灰边框。
- 状态使用小徽标，不使用大面积色块。

### 2.3 侧栏导航

侧栏只放工作台核心入口：

- 我的工作台
- 团队协作
- 项目空间

`设备与 Agent` 不是阶段内主页面，当前先作为我的工作台里的右侧区块。

当前实现说明：

- `/` 已按 `我的工作台` 落地。
- `/team` 已按 `团队协作` 落地。
- `/projects` 已按 `项目空间` 落地。
- `/workflows/[workflowId]` 已按 `工作流详情` 落地。
- `设备与 Agent` 当前仍保留在 `我的工作台` 右侧区块中，暂未拆独立页面。

## 3. 我的工作台

### 3.1 定位

默认首页。用户进入后第一眼只回答一个问题：我现在应该推进哪一件事。

### 3.2 页面结构

左侧主列：

- 当前任务控制台
- 排队任务

右侧副列：

- 工作流时间线
- 团队快照
- 本地设备与 Agent 状态

### 3.3 当前任务控制台

必须展示：

- 任务标题
- 所属项目
- 所属工作流
- 当前步骤
- 当前状态
- 本地目录
- 默认命令
- 队列长度

必须提供动作：

- 开始
- 打开本地
- 打开终端
- 启动命令
- 完成
- 阻塞
- 中断
- 跟进
- 转交

动作分组：

- 主操作：开始、打开本地、启动命令、完成
- 说明型操作：阻塞、中断、跟进、转交

### 3.4 排队任务

排队任务只做次级展示：

- 标题
- 项目
- 当前步骤
- 优先级或进入队列时间

不允许抢占当前任务主视觉。

## 4. 团队协作

### 4.1 定位

展示团队中每个人类线程的占用情况，帮助判断谁在忙、谁被卡住、谁可以接任务。

### 4.2 页面结构

左侧主列：

- 团队成员线程列表
- 阻塞与中断列表

右侧副列：

- 选中成员详情
- 该成员当前任务
- 该成员队列
- 最近交接事件

### 4.3 成员线程列表

每个成员卡片展示：

- 姓名
- 当前状态
- 当前任务
- 队列长度
- 最近更新时间
- 阻塞原因摘要

状态展示：

- 空闲
- 处理中
- 阻塞
- 中断
- 离线

### 4.4 团队动作

MVP 内保留轻操作：

- 查看成员当前任务
- 查看成员队列
- 从当前任务发起转交
- 查看阻塞原因

不做绩效报表，不做复杂权限管理。

## 5. 项目空间

### 5.1 定位

项目空间是工作上下文入口，不是传统后台 CRUD。它回答：这个项目有哪些事项、工作流和本地执行上下文。

### 5.2 页面结构

左侧主列：

- 项目列表
- 项目概览
- 进行中的工作流

右侧副列：

- 快速创建事项
- 项目本地上下文
- 默认命令
- 最近活动

### 5.3 项目列表

每个项目展示：

- 项目名
- 描述摘要
- 本地目录
- 默认命令
- 活跃工作流数量
- 最近更新时间

### 5.4 项目概览

选中项目后展示：

- 项目名称
- 当前活跃事项
- 最近工作流
- 本地路径
- 默认命令

### 5.5 创建事项

从项目空间发起事项：

- 输入事项标题
- 输入事项说明
- 选择事项类型
- 创建后进入对应工作流详情

事项类型先使用静态模板，不进入流程设计器。

## 6. 工作流详情

### 6.1 定位

展示单个工作流的完整执行过程，帮助追踪状态、上下文和事件历史。

### 6.2 页面结构

左侧主列：

- 工作流标题与状态
- 当前步骤
- 任务链
- 当前任务动作入口

右侧副列：

- 时间线
- 参与者
- 项目上下文
- 本地执行记录

### 6.3 任务链

任务链展示：

- 步骤名称
- 任务标题
- 执行人
- 当前状态
- 完成时间或更新时间

展示形态参考 GitHub issue / pull request 的纵向事件流，而不是看板。

### 6.4 时间线

时间线展示：

- 任务创建
- 开始
- 完成
- 阻塞
- 中断
- 跟进
- 转交
- 本地 Agent 事件
- CLI 回调事件

事件 payload 只展示关键字段：

- `command`
- `cwd`
- `shell`
- `processId`
- `exitCode`
- `status`

## 7. 实施顺序

建议按以下顺序实现：

1. 抽出共享工作台壳层：轻侧栏、内容容器、GitHub 风格按钮和面板。
2. 重做默认首页为 `我的工作台`。
3. 拆出 `团队协作` 页面。
4. 拆出 `项目空间` 页面。
5. 拆出 `工作流详情` 页面。
6. 把现有首页中的设备、token 和时间线能力迁移到合适页面或区块。

## 8. 不做范围

- 不做后台管理菜单。
- 不做复杂项目权限配置。
- 不做流程设计器。
- 不做报表型团队分析。
- 不做营销型首页。
