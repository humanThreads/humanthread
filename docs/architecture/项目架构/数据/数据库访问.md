# 数据库访问

代码入口：`packages/db`。运行时代码通过 Prisma client 和领域服务访问数据库；Web 路由与 MCP 只编排鉴权、校验和服务调用，不直接导入 Prisma 写知识表。

## 项目范围访问

- 项目知识请求必须显式携带 `projectId`。访问层以 `knowledgeProjectDigest(projectId)` 计算项目摘要，并在读取 Job 或 Batch 时同时匹配 ID 与 `projectDigest`。
- 读取 Job/Batch 前调用 `assertCanReadProject`；提交、重试和审核前调用 `assertCanWriteProject` 或 `assertCanWriteKnowledgeBatch`。
- 已知项目但资源属于其他项目时返回 404，而不是 403，避免通过响应状态泄露跨项目资源是否存在。
- MCP 的 `prepare_knowledge_job`、`submit_knowledge_batch`、`get_knowledge_job`、`get_knowledge_batch_progress` 均要求 `projectId`，并分派到与 Web API 相同的服务。

## 服务边界

| 服务 | 职责 |
| --- | --- |
| `resolveKnowledgePolicy` / `evaluateKnowledgePublish` | 按“来源/类型精确覆盖 -> 项目策略 -> 平台安全默认”合并策略，再结合平台派生门禁返回 `auto_publish` 或 `review_required` 及原因 |
| `createKnowledgeJob` | 用项目、任务、模板版本、策略版本和来源快照确定性创建幂等 Job，并校验模板/来源状态 |
| `initializeProjectKnowledge` | 幂等补齐项目知识策略和四种生成模式的内置模板：项目初始化、任务完成、定时更新、手工更新 |
| `backfillProjectKnowledge` / `prepareKnowledgeJobForSubmission` | 为项目创建早于知识初始化能力、或初始化失败的项目幂等补齐策略、模板、Job 和 Task；不传 `mode` 时修复初始化 Job，传入 `mode + dedupeIdentity` 时在同一项目知识库创建后续 Job；随后把 `queued` Job 推进到 `worker_running`，并返回提交所需的 `jobId`、`templateDigest` 和来源快照 |
| `submitKnowledgeBatch` | 锁定完整 Job 行，校验状态、模板版本/摘要、策略版本和来源快照身份；服务端重新派生证据、来源、脱敏和冲突门禁后幂等创建批次和条目 |
| `submitKnowledgeBatchForIngestion` | 调用批次提交；全自动批次继续调用不可变发布服务，人工审核批次保持 `review_required` |
| `getKnowledgeBatchProjection` | 读取批次状态、进度、失败分类和消息 |
| `retryKnowledgeBatch` | 仅允许瞬时失败从持久化的 `failedStage` 恢复；永久失败要求新提交 |
| `decideKnowledgeBatch` | 审核批准或拒绝条目，调用版本发布事务；拒绝必须提供原因 |
| `publishKnowledgeBatch` | 将审核结果归档为不可变的 `KnowledgeEntryVersion` 并更新条目投影 |
| `getKnowledgeEntry` / `listKnowledgeEntryVersions` | 读取当前知识投影和追加版本历史 |

自动发布必须同时满足：项目启用自动发布、来源和条目类型在允许列表、平台校验的证据完整、平台敏感内容扫描通过、平台冲突检查通过、锁定 Job/source snapshot 表明来源仍有效、置信度达到阈值，并且对应的删除、失效或替代开关已开启。Worker 提交的布尔门禁不可覆盖平台结果；任一检查不可用或失败即进入人工审核。

## 事务与幂等

- 提交、重试和审核均生成确定性 `CommandReceipt`；重复命令返回原结果或明确的 `command_in_progress` 冲突。提交、发布和回填事务使用 `maxWait = 5s`、`timeout = 30s` 的上界。
- Job、Batch 和 Entry 的关键写路径使用完整行 `FOR UPDATE` 当前读与版本条件更新；同一批次按 `stableKey` 稳定排序获取 Entry 锁，避免并发提交、重复发布和旧基线覆盖新版本。
- `KnowledgeEntryVersion` 为追加记录。`update` 新建版本并保留旧版本；`supersede`、`expire`、`delete` 也生成新的终态版本，不原地删除历史。
- Stage 1 完成知识版本归档后不宣称已建立检索索引；`KnowledgeEntry.searchable` 只有在 Stage 2 索引激活成功后才能置为 `true`。

## 项目范围 API

| 方法与路径 | 权限 | 主要结果 |
| --- | --- | --- |
| `POST /api/projects/:projectId/knowledge/jobs/:jobId/submissions` | 项目写权限 | 202 返回 `batchId`、接收时间、状态和进度；全自动批次继续归档，审核批次停在 30%；非法模板/条目为 400，跨项目为 404，冲突为 409 |
| `GET /api/projects/:projectId/knowledge/jobs/:jobId` | 项目读权限 | 返回项目范围内的 Job 投影 |
| `GET /api/projects/:projectId/knowledge/batches/:batchId` | 项目读权限 | 返回批次状态、进度和失败信息 |
| `POST /api/projects/:projectId/knowledge/batches/:batchId/retry` | 项目写权限 | 从 `failedStage` 重试瞬时失败；不可重试或永久失败为 409 |
| `POST /api/projects/:projectId/knowledge/batches/:batchId/decision` | 项目写权限 | 执行部分或全量批准/拒绝；拒绝缺少原因为 400 |

所有批量和 Job 路由都从 `projectId` 重新计算项目摘要，不接受客户端直接提交摘要。提交路由对 `templateDigest` 要求 32 位小写 MD5，并限制每条批次最多 500 个候选条目。

## MCP 访问

| 工具 | 用途 |
| --- | --- |
| `prepare_knowledge_job` | 修复未初始化项目的知识域；省略 `mode` 时准备初始化 Job，传入 `mode + dedupeIdentity` 时在同一项目知识库准备后续批次 Job；推进到可提交的 `worker_running`，重复调用返回同一 Job |
| `submit_knowledge_batch` | 为可写项目中的 KnowledgeJob 提交候选批次 |
| `get_knowledge_job` | 读取可访问项目中的 KnowledgeJob |
| `get_knowledge_batch_progress` | 读取可访问项目中知识批次的接收和处理进度 |

MCP 不直接写入 Prisma；它与 Web API 共用 `packages/db` 的项目鉴权、幂等提交和状态转换，并调用 `submitKnowledgeBatchForIngestion`，不自行跳过自动发布编排。

## 回填访问

`prisma/backfill-knowledge-domain.mjs` 是部署期脚本，使用 Prisma 直接读取旧 `KnowledgeCandidate`、Document 和 DocumentRevision。默认 dry-run 只输出脱敏摘要与待写入数量；`--apply` 才在事务中按“策略 -> Job -> Batch -> Item -> Entry -> Version -> Relation”顺序写入，结束后要求再次 dry-run 验证无待写入行。计划错误或候选不适格时不写部分实体。脚本不经过在线 API，也不得在未指定目标数据库时执行。
